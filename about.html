核心功能解析

穿透式重疊分析

透過 yfinance 即時抓取成分股並交叉比對。揭露兩檔 ETF 之間高達 80% 以上的重疊率，防止假分散投資。

7日/30日位階診斷

比對當前市價與歷史區間。以「7日最高」或「區間整理」等直觀標籤，輔助投資人判斷基期高低。

產業曝險預警

自動分類成分股產業屬性。預警特定產業（如半導體 66%）的集中風險，協助調整資產配置。

智慧推薦引擎

根據風險等級過濾 SQL 資料庫。針對診斷後的風險缺口，主動提供「低相關、穩健評級」的替代標的。

診斷報表匯出

一鍵產出正確的量化報告。包含所有成分股明細與風險重疊權重，方便投資人紀錄與追蹤。

常見問題 Q&A

許多熱門 ETF 追蹤相似指數。本系統透過 OII 重疊強度指數 提醒投資人，購買名字不同的 ETF 不代表風險已分散，幫助避開管理費浪費。

評級是綜合標的的歷史報酬穩定度、費用率以及波動度所產生的指標。我們會根據您設定的風險等級，自動篩選出最符合需求的優質標的。

這是為了維持資料的誠實性。約 80% 的比例已涵蓋核心成分股，其餘部分可能包含現金部位或資料庫尚未錄入的標的，這已足以提供有效的集中度預警。

我的推薦引擎採用三階段機制：首先透過 SQL 過濾依據您的風險等級篩選標的，接著透過量化評分模型（整合殖利率、Beta值與報酬穩定度）產出 1-5 星評等，最後進行成分股重疊度交叉驗證，確保推薦出的標的能有效達成資產分散的效果。

我導入了 Flask-Caching (Memoization) 機制。金融數據 (如成分股、行情) 變動頻率在短期內相對穩定，我將其快取在記憶體中 (1-24小時)。這樣不僅大幅降低了對外部 API 的負擔，也確保使用者在進行第二次查詢時，能夠實現毫秒級的秒開體驗。

系統在所有資料獲取模組中均加入了 try-except 例外處理。當 API 連線異常時，系統會自動捕捉錯誤並確保程序不崩潰，同時優先讀取快取中的歷史資料或顯示「資料不足」提示，這能確保使用者的操作體驗始終流暢，不會因為單點故障導致整個頁面無法顯示。

OII (Overlap Intensity Index) 是本系統的核心指標。計算上採用權重平方加權法，能放大高佔比成分股的重疊影響。若 OII 指數過高（>15），代表您的資產高度集中在少數個股，即便買了兩檔名字不同的 ETF，本質上風險並未分散，這是本系統用來預警「假分散投資」的關鍵指標。

我採用了「分級快取策略」：
1. 行情數據 (行情/位階)：設定為 1 小時更新，確保診斷準確性。
2. 成分股數據 (OII/產業)：設定為 24 小時更新，因成分股變動頻率極低，此舉可大幅節省 API 資源並防護速率限制。
3. 自動容錯：若外部 API 連線失敗，系統會自動 fallback 至最後一次有效的快取紀錄，保證系統的極高可用性。
